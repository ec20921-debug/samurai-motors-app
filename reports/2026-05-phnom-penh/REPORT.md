## 2. 主要成果

### 2-1. 🏪 In-store オプション追加（出張のメイン成果）

現地スタッフからの強いフィードバックを受け、ミニアプリに「店舗で受ける」選択肢を追加。来店顧客は出張料 $2 がかからない。

- **タブ切替 UI**（🚗 Delivery / 🏪 In-store）追加
- 店舗モード: Leaflet で **店舗座標固定マップを埋め込み**（外部 Google Maps リンクを撤廃しフロー離脱防止）
- 出張モード: **GPS で現在地を自動取得しピン自動設置**（タップ手間削減）
- BOOKINGS シートに「サービスタイプ」列追加（33 列目）
- 通知メッセージで店舗/出張を完全分岐
  - 顧客: `🏪 In-store: $0` / `🚚 Delivery fee: $2`
  - 管理者: `[🏪 店舗作業]` / `[🚗 出張作業]` タグ
  - 店舗予約には「Please come to our office + 店舗住所」案内、駐車場ヒアリング省略

→ 仕様書: [`docs/SPEC_v8.md`](../../docs/SPEC_v8.md)

### 2-2. 🇰🇭 業務ボット 完全クメール語ファースト化

カンボジア人スタッフ（Run Kosal）が一人で業務を回せるよう、業務 Bot (`job-manager.html`) を全面ローカライズ。

| 領域 | Before | After |
|---|---|---|
| カウンター | `合計` `待機中` `完了` | **`សរុប` / `រង់ចាំ` / `បានបញ្ចប់`**（日本語は小さくサブ） |
| ステータス | `⏳ 待機中` | **`⏳ រង់ចាំ`** |
| ジョブカード | 店舗/出張区別なし | **`🏪 STORE / នៅហាង` / `🚗 DELIVERY / ដឹកជញ្ជូន`** バッジ |
| プラン表記 | `✨W(W) ・ セダン` | **`✨ WASH ・ Sedan`**（重複削除） |
| ジョブ詳細 | 日本語ラベル | **クメール語ラベルを大、日本語サブ**（時間 / 料金 / Plan / 車種 / 場所） |
| 「ジョブ開始」ボタン | 控えめ | **大きくゴールドグラデ + シャドウ強化**、クメール語メイン |

### 2-3. 🐛 致命バグ修正

| バグ | 影響 | 修正 |
|---|---|---|
| **QR が顧客に 2 回送信** | 顧客困惑 | `sendPaymentQR` に LockService 追加 + `apiJobFinal` の二重呼び出し停止 |
| **リマインダー時刻が「Sat Dec 30 1899 11:00:00」** | 顧客困惑（致命的） | スプレッドシートの時刻セル（Date 1899-12-30 ベース）を `HH:mm` 整形対応 |
| **GLASS 単体予約で「Cannot read properties of null (reading 'letter')」** | 予約失敗 | `plan ? plan.letter : null` ガード追加 |
| **「Ron」表記がスタッフ本名と違う** | 顧客信頼 | 6 箇所を `Run Kosal` に統一 |
| **「remove valuable items」表現** | 顧客への不信感 | 「Please be ready / drive safely」にニュートラル化 |

### 2-5. 📊 顧客導線設計

ローカルスタッフとのディスカッションで以下の段階的導線に着地：

```
1. 事務所で洗車・ガラスコーティング体験（リアル接点）
   ↓
2. 「家でもこのサービスが受けられる」と訴求
   ↓
3. アプリで予約 + デリバリー費 $2 → 出張作業
   ↓
4. リピート顧客化
```

→ **「リアル → デジタル」段階的導線** がカンボジア市場のデジタル成熟度に合うという仮説。

## 4. 設計判断の記録

| 判断 | 採用案 | 理由 |
|---|---|---|
| 場所選択画面のデフォルトタブ | **「🚗 Delivery」** | 既存予約パターンが出張主流。来店は新規導線として追加 |
| 店舗マップの操作性 | **完全に操作不可（パン・ズーム禁止）** | 場所確認用、予約フロー離脱防止 |
| 「Open in Google Maps」リンク | **撤廃** | フロー離脱の原因。住所は予約完了後の Telegram で送信 |
| 駐車場ヒアリング | **出張のみ送信、店舗はスキップ** | 店舗来店時は階数等不要 |
| Windows パスワード | **変更しない**（貸出 PC ポリシー） | 返却時の戻し忘れリスク回避、AnyDesk → Chrome Remote Desktop の無人アクセス PW で防御線 |
| リモート手段 | **Chrome Remote Desktop**（AnyDesk 不採用） | 完全無料・業務利用OK・Google アカウント認証で運用統合 |
| Google アカウント分離 | **samuraimotors.kron@gmail.com を新規作成** | メイン samuraimotors.japan の権限を肩代わりさせない |
| UI ローカライズ | **クメール語ファースト、日本語サブ** | 現場スタッフが主役、管理者はサブ的に確認 |
| ポスター文字レンダリング | **AI に書かせず Canva 後乗せ** | 価格・電話・他言語の誤り回避 |

## 5. 学び・気づき

### 5-1. Run Kosal 君の業務理解度・伝達能力が高い
- トレーニング成功 + 業務オーナーシップ確立
- 顧客向け説明をスタッフに任せられる体制ができた
- 今後の遠隔運用の土台になる

### 5-2. 「リアル → デジタル」導線設計
- カンボジア市場のデジタル成熟度に合った戦略
- 「いきなりアプリで予約」より「体験 → アプリで再予約」の方が成約率高い仮説
- 店舗来店からの転換が鍵

### 5-3. UI 改善（自動 GPS・自動ピン）は小さなコード変更で UX が劇的に変わる
- ローカル目線のフィードバックが効いた事例
- 数行のコードで顧客の手間が大幅削減

### 5-4. クメール語ファースト化のインパクト
- スタッフが業務ボットを使う心理的障壁が下がった
- 翻訳ではなく「現地語をメインに据える」設計判断が効く
- 日本語は補助情報として併記、管理者向けの安心感も担保

### 5-5. リモート開発の限界と現地立ち会いの価値
- リモートでは見えない「現場運用の罠」が現地で次々判明
  - 例: 業務ボットのジョブ一覧で店舗/出張が区別できない
  - 例: リマインダーが 1899 年表記
  - 例: QR が 2 回送信される
- **現地で実機テストして、即修正サイクル**を回せたのが最大の収穫

### 5-6. 高速イテレーションの効果
- 1 日に 5〜7 PR をマージ → 即デプロイ → ロン君が即テスト → フィードバック → 即修正
- clasp deploy で URL を変えずにバージョン更新できる運用が確立 → ノンストップ改修
- Notion + GitHub + 手順書の 3 軸で情報が分散せず追える状態を維持
