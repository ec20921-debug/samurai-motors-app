## 4. 設計判断の記録

| 判断 | 採用案 | 理由 |
|---|---|---|
| 場所選択画面のデフォルトタブ | **「🚗 Delivery」** | 既存予約パターンが出張主流。来店は新規導線として追加 |
| 店舗マップの操作性 | **完全に操作不可（パン・ズーム禁止）** | 場所確認用、予約フロー離脱防止 |
| 「Open in Google Maps」リンク | **撤廃** | フロー離脱の原因。住所は予約完了後の Telegram で送信 |
| 駐車場ヒアリング | **出張のみ送信、店舗はスキップ** | 店舗来店時は階数等不要 |
| Windows パスワード | **変更しない**（貸出 PC ポリシー） | 返却時の戻し忘れリスク回避、AnyDesk → Chrome Remote Desktop の無人アクセス PW で防御線 |
| リモート手段 | **Chrome Remote Desktop**（AnyDesk 不採用） | 完全無料・業務利用OK・Google アカウント認証で運用統合 |
| Google アカウント分離 | **samuraimotors.kron@gmail.com を新規作成** | メイン samuraimotors.japan の権限を肩代わりさせない |
| UI ローカライズ | **クメール語ファースト、日本語サブ** | 現場スタッフが主役、管理者はサブ的に確認 |
| ポスター文字レンダリング | **AI に書かせず Canva 後乗せ** | 価格・電話・他言語の誤り回避 |

### 5-2. 「リアル → デジタル」導線設計
- カンボジア市場のデジタル成熟度に合った戦略
- 「いきなりアプリで予約」より「体験 → アプリで再予約」の方が成約率高い仮説
- 店舗来店からの転換が鍵

- ローカル目線のフィードバックが効いた事例
