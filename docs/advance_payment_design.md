## 1. 問題定義

### 現状

飯国さんの ABA 銀行送金履歴（2026-04〜05）:

| 日付 | 受領者 | 金額 | 推定意図 |
|---|---|---|---|
| 7 MAY | RUN KOSAL | -$2,250 | 大口前払い（運転資金） |
| 10 MAY | RUN KOSAL | -$500 | 前払い追加 |
| 12 MAY | RUN KOSAL | -$20 | 小口送金 |
| 28 APR | RUN KOSAL | -$50, -$18.50, -$11 | 小口（複数回） |
| 2 MAY | SOUNG SOPHEAKDEY | -$750 | 別スタッフへ送金 |
| 26 APR | YAGUCHI TAKENORI | -$1,000 | 別件 |

→ これらは **飯国さんのスマホ銀行アプリにしか履歴がなく**、Samurai Motors のシステムでは管理されていない。

### システム側の現状（v7-operations）

| 区分 | 既存対応 | 前払い対応 |
|---|---|---|
| 立替（スタッフが先払い→会社が精算） | ✅ 実装済 | — |
| 会社直払い（会社が直接ベンダーに） | ✅ 実装済 | — |
| **前払い（会社→スタッフ→消費）** | ❌ 不在 | **本設計のスコープ** |
| 給与・賃料の定例タスク | ✅ タスクテンプレで管理 | — |
| パートナー紹介コミッション送金 | ✅ PartnerManager.gs | — |

### 解決すべきこと

1. 飯国さんが前払い送金した時、**手間なく記録**できる
2. ロン君が経費入力する時、**前払いから消費**を選択できる
3. **誰にいくら残高があるか** がリアルタイムで把握できる
4. すべて **統合明細（既存 GSS）** に集約される

| ステークホルダー | 役割 | 主なニーズ | 設計の対応 |
|---|---|---|---|
| **飯国（送金担当）** | 日本側、ABA から送金実行 | モバイルから1分以内で記録、抜け漏れゼロ | **Telegram Bot コマンド `/advance` で1往復入力** |
| **ロン君（現場）** | カンボジア、経費入力 | 選択肢が増えても迷わない、残高を把握したい | expense-internal.html に「支払元」3択、選択時に**自分の残高表示** |
| **鈴木（CEO/開発）** | 設計・実装 | 既存スキーマ最大流用、追加コスト最小 | **既存「経費」シート拡張 + 新規1枚追加**で済む |

## 4. operations GSS のスキーマ変更

### 4-1. 新規シート: `前払い送金`

| 列 | 型 | 説明 |
|---|---|---|
| 送金ID | String | `TRF-YYYYMMDD-NNN` 形式（generateDateSeqId 流用） |
| 登録日時 | DateTime | 入力時刻 |
| 送金日 | Date | 実際の送金日（銀行アプリ上の日付） |
| 送金者 | String | 飯国 / 鈴木 / etc.（スタッフマスターから） |
| 送金者 Chat ID | String | Bot 経由なら自動 |
| 受領者スタッフID | String | スタッフマスターと紐付け（STAFF-XXX） |
| 受領者名 | String | 表示用（クメール現地名でも可） |
| 金額 | Number | 数値 |
| 通貨 | Enum | USD / KHR / JPY |
| 用途 | String | "運転資金" / "携帯代" / "賃料" など |
| 入金方法 | Enum | ABA送金 / 現金手渡し / その他 |
| 銀行Trx ID | String | ABA の取引ID（任意） |
| スクショ Drive | URL | 銀行アプリのスクショ画像（任意） |
| ステータス | Enum | 有効 / 取消 / 完了消化 |
| 累計消化額 | Number | この送金分から経費で何ドル使ったか（動的計算 or 集計バッチ） |
| 残高 | Number | 金額 - 累計消化額（=今この送金の残り） |
| メモ | String | 自由 |

→ **計17列**。残高は QUERY 式 or 日次バッチで更新。

### 4-2. 既存シート `経費` の拡張

現状（ExpenseManager.gs:24-30）:
```
'経費ID', '登録日時', '取引日', '品目・摘要', '金額', '通貨',
'取引先', '勘定科目', '登録者', '登録者 Chat ID',
'レシート写真', 'OCR原文', 'ステータス', 'メモ',
'立替区分', '精算先', '精算期限', '精算日', '精算方法', '関連タスクID'
```

**追加する列**:
- `紐付き送金ID`: 前払い消費の場合に紐付ける `TRF-YYYYMMDD-NNN`（任意、立替/会社直払いなら空）

**変更する列**:
- `立替区分` の選択肢を **3 値** に拡張: `立替` / `会社直払い` / **`前払い消費`**

→ コード変更は ExpenseManager.gs の `EXPENSE_PAYMENT_TYPES_` 配列に1値追加、新規列を `EXPENSE_HEADERS_` に追加するだけ。

### 4-3. 計算ロジック

**スタッフ別残高** = Σ（このスタッフへの送金合計） − Σ（このスタッフの前払い消費合計）

```javascript
// 概念コード
function getStaffBalance(staffId) {
  const inflows  = sumColumn('前払い送金', '金額', { '受領者スタッフID': staffId, 'ステータス': '有効' });
  const outflows = sumColumn('経費',       '金額', { '登録者スタッフID': staffId, '立替区分': '前払い消費' });
  return inflows - outflows;
}
```

## 5. UX 設計

### 5-1. 飯国の送金入力 — Telegram Bot `/advance`

**フロー**（Bot との対話形式）:

```
飯国: /advance
Bot:  💰 前払い送金を記録します。受領者は？
      [ロン] [SOUNG] [YAGUCHI] [その他]
飯国: ロン
Bot:  金額は？（数字のみ、USD を想定）
飯国: 2250
Bot:  通貨は？ [USD] [KHR] [JPY]
飯国: USD
Bot:  用途のメモを書いてください（例: 運転資金）
飯国: 5月の運転資金
Bot:  ABA のスクショを送ってください（スキップ可）
飯国: [画像]
Bot:  確認:
      ・受領者: ロン
      ・金額: $2,250
      ・用途: 5月の運転資金
      ・スクショ: あり
      これでよければ「OK」、修正なら「取消」
飯国: OK
Bot:  ✅ 記録しました（TRF-20260507-001）
      ロンの累計残高: $2,720
```

**実装ポイント**:
- 業務Bot に新規ハンドラ追加（既存の TaskManager と同じ会話状態管理パターン）
- **飯国の chat_id を ScriptProperties に登録**（`OWNER_CHAT_ID_LIST` = ['飯国chat_id', '鈴木chat_id']）→ それ以外からは `/advance` を受け付けない
- スクショは Drive に保存、リンクをシートに記録（既存の `saveReceiptPhoto_` パターン流用可）

### 5-2. ロン君の経費入力 — expense-internal.html 拡張

現状の「立替」「会社直払い」トグルを **3 ラジオボタン** に拡張:

```
┌─────────────────────────────────┐
│ 支払元 / ការទូទាត់               │
│ ○ 立替（自分が払った）           │
│ ○ 会社直払い                     │
│ ● 前払いから / មុនបង់ ⭐          │
│                                  │
│   💰 残高: $2,720                │ ← 「前払いから」選択時のみ表示
│   ⚠️ 残り少ないです（任意警告）  │
└─────────────────────────────────┘
```

**実装ポイント**:
- ミニアプリ初期化時に `/api/expense_meta` を叩いて自分の残高を取得
- 「前払いから」選択 → 残高表示 → 金額入力時に残高超過警告
- 経費登録時に `支払元='前払い消費'` + `紐付き送金ID=<最古の有残高送金ID>` を自動セット

**紐付き送金IDの決め方**: FIFO（古い送金から先に消化）が最もシンプル。

### 5-3. 鈴木/飯国/金子 の閲覧 — 統合明細 GSS

統合明細 GSS に以下のシート/ビューを設置（**operations GSS から IMPORTRANGE で取得**）:

| ビュー | 内容 | 数式 |
|---|---|---|
| 月次取引一覧 | 全送金+全経費を時系列で | `IMPORTRANGE(operations_id, "前払い送金!A:Q") + IMPORTRANGE(... 経費!A:V)` を QUERY で結合 |
| 残高サマリ | スタッフ別現在残高 | QUERY で SUM by staffId |
| 勘定科目別集計 | 月別 × 勘定科目で合計 | QUERY with PIVOT |
| 前払い消化トラッキング | 各送金ID の消化率 | 送金IDごとに紐付き経費を集計 |

→ **operations 側の GAS は何も書かない**。統合明細側の数式のみで完結（バッチ不要）。

⚠️ **要確認**: 統合明細 GSS の現状構造（タブ名・列定義）。設計の最終段では合わせ込みが必要。

## 7. 移行戦略

**過去分の取り扱い**:

| 期間 | 対応 |
|---|---|
| 〜2026-04 以前 | バックフィル**しない**（過去は資料として銀行アプリのみに残す） |
| 2026-04〜05 の既存送金（$2,250 等） | **飯国が手動で `/advance` で1件ずつ入力**（バックデート可、送金日フィールドで実日付指定） |
| 2026-05-18 以降の新規送金 | 必ず `/advance` で記録 |

→ ロン君の経費はそのまま継続。区分が増えるだけなので互換性あり。
