## 1. 目的（このタスクで作るもの）

「テレグラム限定の特価キャンペーン（例: 5ドル特価）」を、**現場スタッフ（ロン君）が
スマホだけで店舗・出張の両方に対応できる**ようにする。当初設計（`SPEC_CampaignBroadcast.md` §4）は
「ロン君が予約シートに直接記入」だったが、これは**実質パソコン作業**で現場では破綻する。

### ゴール
- ロン君が **業務Bot の job-manager.html ミニアプリ**から、特価予約を**タップ中心**で登録できる。
- **店舗（来店・即完結）/ 出張（後日訪問・カレンダー必要）の両対応**。
- **$5 をコードに焼かず**、キャンペーンを**シートで定義**（将来いろんな販促を行を足すだけで増やせる）。
- 公開価格（30%オフ）・自動QR決済には**一切影響を与えない**。

## 3. 壊してはいけない大原則（最重要）

`SPEC_CampaignBroadcast.md` §1 の「2つの価格を物理的に分離する」を厳守する。

| | A: 公開キャンペーン（30%オフ） | B: テレグラム限定特価（今回の対象） |
|---|---|---|
| 価格の出どころ | `料金設定`シート → booking.html 自動反映 | **`特価キャンペーン`マスター。公開しない** |
| 予約経路 | booking.html ミニアプリ（自動） | job-manager.html の新画面（ロン君が手動登録） |
| 価格計算 | `createBooking()` | **`createManualBooking()`（新設・固定額）** |
| 支払い | 自動QR（`QR_CODES` / `PaymentManager`） | ABA静止画QR→スクショ目視（完全手動） |

### ❌ 絶対にやってはいけない
- 特価を `料金設定` シートに入れる（booking.html 経由で全公開客に漏れる）。
- 特価を自動QRシステム（`QR_CODES`/`PaymentManager`）に通す（経路が混ざる）。
- 公開用 `createBooking()`（`BookingLogic.gs:558`）に特価の分岐を足して汚す。
- `status`(進行状態) 列に `paid` を入れる（決済は `決済状態` 列に一元化）。
- トークン・スプレッドシートID・chat_id 等のハードコード（全て PropertiesService）。

### 言語ルール（CLAUDE.md より）
- 新画面（スタッフ向け）= **クメール語ファースト＋日本語サブ（括弧）**。例: `ចាប់ផ្តើម（作業開始）`
- 管理グループ通知 = **日本語**。
- GASコード・コメント = 英語/日本語（既存に合わせる。本プロジェクトはコメント日本語可）。

## 5. 実装プラン（PC作業でやること）

### 5-1. 新シート `特価キャンペーン`（手動特価マスター）
データ駆動の心臓部。$5はここの1行。セットアップは**Setup系ファイルに置き `.claspignore` で除外**（肥大化ルール）。

| 列 | 例 | 用途 |
|---|---|---|
| `キャンペーンID` | CAMP-5USD | 識別・記録 |
| `名前(クメール)` | …5$… | ミニアプリ表示（km） |
| `名前(日本語)` | 5ドル特価 | ミニアプリ表示サブ＋予約シート記録 |
| `特価(USD)` | 5 | 適用する固定額 |
| `対象サービスタイプ` | 両方 / 店舗 / 出張 | 選べる導線を制御 |
| `有効` | TRUE | ✅だけミニアプリに出す |
| `期間開始` / `期間終了` | （任意） | 期間外は自動で非表示 |
| `メモ` | （任意） | 運用メモ |

### 5-2. 新規 `v7/CampaignBooking.gs`（〜200行目安）
- `manualCampaignList()` — `特価キャンペーン`から `有効=TRUE` かつ期間内の行を返す（ミニアプリのドロップダウン用）。
- `createManualBooking(params)` — **公開 `createBooking` とは別経路**で予約を作る。
  - 入力: `campaignId`, `serviceType`(店舗/出張), `name`, （出張のみ）`date`/`startTime`/`location`, 任意で `chatId`/`vehicleType`。
  - 価格は**マスターの`特価(USD)`固定**（プラン計算しない）。
  - `予約ID`採番、`appendRow` で BOOKINGS へ記録。`料金(USD)`=特価、`キャンペーン名`=マスター名、`サービスタイプ`設定。
  - **店舗**: `進行状態`=`作業完了`相当・`決済状態`=`清算済み`（その場完結）。カレンダー作成しない。
  - **出張**: `進行状態`=`予約確定`・`決済状態`=`未清算`。**カレンダー自動作成**（`createBooking` の `CalendarApp.createEvent` 部分を参考）。
  - `LockService` で排他制御（`createBooking` と同様）。
- `settleManualBooking(bookingId)` — 出張の作業後、`決済状態`=`清算済み` に更新（スクショ目視後にロン君が押す）。
- （任意）作成時に管理グループの該当トピックへ日本語通知。

### 5-3. `v7/Router.gs` にアクション追加
- GET: `manual_campaign_list` → `manualCampaignList()`（`Router.gs:38` 付近の switch に追加）。
- POST: `manual_campaign_create` → `createManualBooking(params)`（`Router.gs:81` 付近）。
- POST: `manual_campaign_settle` → `settleManualBooking(bookingId)`。

### 5-4. `job-manager.html` に「🎫 特価予約」画面を追加
- メニュー/タブに「🎫 特価予約（特価キャンペーン）」を1枚追加。
- 流れ:
  1. `manual_campaign_list` を呼び、**有効キャンペーンをドロップダウン表示**（クメール語名＋日本語サブ）。
  2. **店舗 / 出張** を選択（マスターの`対象サービスタイプ`で出し分け）。
  3. 顧客名を入力。
  4. **出張のみ**: 日時＋場所（Telegram位置共有 or Googleマップリンク貼付。`booking.html` の入力UI流用）。
  5. 確定 → `manual_campaign_create` を POST。
  6. 出張は作成後、施工は既存の作業一覧に出る。作業後に「💵清算」→ `manual_campaign_settle`。
- 言語: クメール語ファースト＋日本語サブを既存トーンに合わせる。

## 6. スタッフ導線（完成イメージ・キャンペーン非依存）

### 店舗（来店・その場完結）
1. 客が一斉送信画面を提示。
2. ロン君: ミニアプリ「🎫 特価予約」→ キャンペーン選択 → 店舗 → 名前入力 → 確定。
3. ABA静止画QRを見せる → 客が支払い → スクショを目視確認。
4. 記録は手順2で予約シートに `作業完了`/`清算済み` で入る（カレンダー不要）。

### 出張（後日訪問）
1. 集客: 予約Bot一斉送信 → 客が予約Botに返信 → 既存の1顧客1トピック生成。
2. ロン君が日程・場所を客とやり取り（既存チャット）。
3. ミニアプリ「🎫 特価予約」→ キャンペーン選択 → 出張 → 名前/日時/場所 → 確定。
   → 予約シート記録（`予約確定`/`未清算`）＋**カレンダー自動生成**。
4. 当日: 既存の作業一覧に出るので、通常通り開始/終了/写真（3方向配信）。
5. 作業後: ABA静止画QR→スクショ目視→「💵清算」で `清算済み`。
