## 0. このドキュメントの位置づけ

「テレグラム限定の5ドル特価」と「公開の30%オフ」を**混ぜないための土台**を定義する。
実装に入る前に、ここで経路・シート・オペレーションを確定させる。

関連する既存資産（流用元）:
- `PaymentManager.gs` `checkUnpaidReminders()` — 顧客行ループのテンプレ
- `PaymentManager.gs` `sendQRImage()` — Driveリンクから file_id を抽出して送信する処理
- `TelegramAPI.gs` `sendPhoto` / `sendPhotoFromDriveId` / `sendMediaGroup`
- `SheetHelpers.gs` `appendRow` / `findRow` / `updateRow` / `generateDateSeqId`
- `Setup.gs` `createDriveFolders()` — Driveフォルダ作成パターン

## 1. 最重要原則 — 2つの価格を物理的に分離する

頭の中で混ざりがちな2つを、システム上も完全に分離する。

| | A: 公開キャンペーン（30%オフ） | B: テレグラム限定特価（例: 5ドル） |
|---|---|---|
| 誰が見る | 全員（誰でもミニアプリで見れる） | 一斉送信を受け取った既存客だけ |
| 価格の出どころ | `料金設定`シート → booking.html が自動反映 | **どこにも公開しない。ロン君が手動入力** |
| 予約経路 | ミニアプリ（自動） | Telegramでロン君と直接やり取り（手動） |
| カレンダー | 自動登録 | ロン君が手動登録 |
| 支払い | 既存の自動QR決済フロー（`QR_CODES`シート） | **飯泉さんのABA静止画QR（ロン君の携帯写真）→ スクショで目視確認 → 手動で清算済み** |

### ❌ 絶対にやってはいけないこと
- **5ドルを `料金設定` シートに入れる** → booking.html に直結しているため、全公開客に5ドルが漏れる。
- 5ドル特価の支払いを既存の自動QRシステム（`QR_CODES` / PaymentManager）に通す → 経路が混ざる。5ドルは**静止画QR＋スクショ目視確認**の完全手動経路に隔離する。

→ 今回作るのは **「Bの集客導線（一斉送信）とその記録・管理」**。価格ロジックそのものは触らない。

## 2. シート設計

### 2-1. `顧客`シートに2列追加

既存列（顧客ID / チャットID / ユーザー名 / 氏名 / 電話番号 / 言語 / トピックID / 登録日時 / 最終連絡日時）に追加:

| 追加列 | 型 | 用途 |
|---|---|---|
| `配信対象` | チェックボックス（TRUE/FALSE） | ✅で送る。ブロック客・苦情客はFALSEで除外。デフォルトTRUE。 |
| `最終配信日時` | 日時 | 直近いつ送ったか（連投防止の目安） |

月曜会議では、このチェックボックスで「今週は誰に送るか」を選ぶ。

### 2-2. 新規シート `キャンペーン`（配信台帳 — 1行=1配信）

| 列 | 例 | 入力者 |
|---|---|---|
| `キャンペーンID` | CAMP-20260601-001 | 自動 |
| `配信予定日` | 2026-06-01 | 人 |
| `タイトル` | 6月第1週 5ドル特価 | 人 |
| `本文(クメール)` | …5$… | 人 |
| `本文(英語)` | …$5… | 人 |
| `写真ドライブリンク` | https://drive.../file/d/xxx | 人 |
| `ボイスドライブリンク` | （任意） | 人 |
| `ステータス` | 下書き / 送信済み | 自動＋人 |
| `送信数` | 48 | 自動 |
| `失敗数` | 2 | 自動 |
| `送信日時` | 2026-06-01 10:00 | 自動 |
| `反応メモ` | 3件返信、1件来店 | 人（週末に追記） |
| `予約獲得数` | 2 | 人 |

### 2-3. 新規シート `配信ログ`（明細 — 1行=1人×1配信）

「このキャンペーンを誰に送ったか」を正確に追跡。後からセグメント送信（未反応者だけ再送など）の土台になる。

| 列 | 例 |
|---|---|
| `キャンペーンID` | CAMP-20260601-001 |
| `顧客ID` | CUST-20260510-003 |
| `氏名` | Sok Dara |
| `チャットID` | 12345678 |
| `送信結果` | OK / FAILED |
| `送信日時` | 2026-06-01 10:00:03 |

### 2-4. Drive フォルダ

`Config.gs` に `DRIVE_FOLDER_CAMPAIGN` を1キー追加。月曜会議で使う写真・ボイスをここに入れ、共有リンク（`ANYONE_WITH_LINK` / `VIEW`）を `キャンペーン` シートに貼る。
送信時は既存 `sendQRImage()` のリンク解析ロジックを流用してDriveから送信。

## 3. 一斉送信の仕組み

### 起動方法（確定）= スプレッドシートのカスタムメニュー

月曜会議で内容を目視確認しながらボタンを押す運用。Telegramコマンドより誤爆が少ない。

```
📢 キャンペーン配信
 ├ ① プレビュー送信（飯泉さん自身にだけ送って確認）
 ├ ② 本番送信（配信対象=TRUE の全員へ）
 └ ③ 反応集計を更新
```

- 必ず**①プレビュー → 目視OK → ②本番**の順。誤送信事故を防ぐ。
- 50人なら1人ごとに `Utilities.sleep(1200)` を挟んでも約1分（GASの6分制限内、Telegramレート制限も安全）。
- 送信しながら `配信ログ` に1行ずつ記録。ブロック等で失敗したら `FAILED` として `失敗数` にカウント。
- `キャンペーン` 行の `ステータス`→送信済み、`送信数`/`送信日時` を自動更新。`顧客.最終配信日時` も更新。

### 自動化（後回し）
まず手動ボタンで安定運用。安定後に「日曜夜に下書き行を自動送信」トリガーを追加検討。今は確実性優先。

## 4. 5ドル特価の現場オペレーション

### 来店（店舗）
1. 客が一斉送信の画面を見せる → 「メッセージ見てくれたんですね、5ドルで！」
2. ロン君が**社用携帯の飯泉さんABA静止画QRを見せる** → 客がスキャンして5ドル支払い
3. 客が**支払いスクショ**を見せる → ロン君が目視で着金確認
4. ロン君が **`予約`シートに直接1行記入**: 客名 / 料金=5 / `サービスタイプ`=店舗 / `進行状態`=completed / `決済状態`=清算済み / `キャンペーン名`=5$特価

### 出張
1. 一斉送信に「**やりたい人は連絡して（先着順）**」のボイス＋テキストを添える
2. 客が予約Botに返信 → 既存の1顧客1トピックでトピック生成
3. ロン君が予約Botで「いつ？場所は？」とやり取り、Googleマップ位置情報を受領
4. ロン君が**手動でGoogleカレンダー登録** ＋ `予約`シートに直接記入
5. 作業後、飯泉さんABA静止画QRで5ドル → スクショ確認 → `決済状態`=清算済み を手動記入

### この設計の良い点
- 公開ミニアプリ（一般客=30%オフ）と手動5ドル導線が完全分離。価格が混ざらない。
- 既存の「1顧客1トピック」「決済状態列」「サービスタイプ列」をそのまま再利用。
- 5ドルが公開価格に絶対漏れない。自動QRシステムにも触れない。

### 手動予約の登録方法（確定）= 当面シート直接記入
ロン君が `予約` シートに1行手書き。頻度が増えたら業務Botに簡易フォーム化を検討。
