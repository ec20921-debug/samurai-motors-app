# VIP 紹介プログラム（撥水コーティング無料モニター連動）

**作成日**: 2026-05-11
**位置づけ**: `WATER_REPELLENT_TROJAN_CAMPAIGN.md` の派生施策（モニター施工を「紹介経由」で広げる）
**運用フェーズ**: Phase 0（手動運用 MVP）→ Phase 3 で予約Bot/ミニアプリへ実装

---

## 1. 目的

撥水コーティング無料モニターを既存顧客の紹介経由で広げ、駐在員コミュニティ内で口コミを連鎖させる。

- 紹介者には**毎回確実なお礼 + 累積マイルストーン特典**を提供し、「どんどん紹介したくなる」設計にする
- 被紹介者は**ガラス3面＋ミラー撥水コーティング無料**で来店
- 紹介経路を `REFERRALS` シートで記録し、後の Phase 3 で deep link 自動化に移行できる構造にしておく

## 2. 報酬設計

### 2-1. 紹介者（既存顧客）への特典

| 累計紹介人数 | 特典 | 補足 |
|---|---|---|
| **1人毎（常時）** | 🎫 **洗車1回無料チケット** | 1人 = 1枚発行。何人でも積み上がる |
| **3人達成ボーナス** | ✨ **ガラスコーティング3面＋ミラー無料**（モニター施工と同等内容） | 紹介者自身がまだ未施工なら本人施工、施工済みなら家族・追加車両に充当可 |
| **5人達成ボーナス** | 🚗 **ボディコーティング 1面無料 or フルコーティング 50% OFF** | どちらかを紹介者が選択 |
| **7人達成（VIPステータス）** | 👑 **駐在任期中ずっと全メニュー10% OFF + 優先予約** | 「永久」ではなく「任期中」とすることで業務側の負担を限定 |

> ※ ボーナスは **累積到達**で発生（1人達成時に毎回チケット → 3人到達で追加ボーナス発火、というイメージ）。チケットには使用期限を付けない（駐在員の利用タイミングを縛らない）。

### 2-2. 被紹介者（友人 / 知人 / 同僚）への特典

- **ガラス3面＋ミラー撥水コーティング無料**（無料モニター施工と同条件）
- 施工完了後、来店時に「次は紹介する側」と一言案内し、ピラミッドを回す

## 5. トラッキング設計（REFERRALS シート）

Phase 0 は手動でシートに記入、Phase 3 でコード自動化に切替える前提のスキーマ。

| 列名 | 型 | 例 | 説明 |
|---|---|---|---|
| `referral_id` | string | REF-20260511-001 | 主キー（日付＋連番） |
| `referrer_id` | string | kamada_ryo | 紹介者の Telegram username or 顧客ID |
| `referrer_name` | string | 鎌田 涼 | 表示用 |
| `referee_name` | string | （カンボジア人友人） | 被紹介者氏名 |
| `referee_contact` | string | 096 713 8456 / @username | 電話 or Telegram ID |
| `referee_lang` | string | km / en / ja | 連絡言語 |
| `booking_id` | string | BK-20260505-001 | 予約成立時に紐付け（未予約時は空） |
| `status` | enum | introduced / contacted / booked / completed / cancelled | 進行状態 |
| `reward_given` | string | 洗車1回無料チケット #001（未使用） | 紹介者への発行物 |
| `bonus_milestone` | string | 3人達成ボーナス発火 | 累積マイルストーン到達時に記入 |
| `notes` | string | 雨季前希望 | 自由記入 |
| `created_at` | datetime | 2026-05-05 18:37 | |
| `updated_at` | datetime | 2026-05-05 19:10 | |

## 6. Phase 0 運用フロー（実装ゼロ）

```
1. 紹介者へ「VIP紹介プログラム」案内メッセージ送信（§4-1, §4-2）
        ↓
2. 紹介者から被紹介者の連絡先（Telegram / 電話）を受領
        ↓
3. REFERRALS シートに新規行追加（status=introduced）
        ↓
4. 被紹介者へ初回コンタクト（§4-3 or §4-4） → status=contacted
        ↓
5. 日程調整 → BOOKINGS シートに手動で予約登録、`notes` 列に「referrer: 〇〇」記入
   → REFERRALS の status=booked, booking_id を紐付け
        ↓
6. 施工完了 → REFERRALS の status=completed
        ↓
7. 紹介者の累計人数を集計
   - 1人毎: 洗車無料チケット発行（reward_given に記入）
   - 3/5/7人到達: ボーナス通知メッセージを紹介者へ送信
        ↓
8. 被紹介者へ「次は紹介する側」案内（来店時に口頭でもOK）
```

## 7. Phase 3 実装時の移行方針

Phase 0 の手動運用で実証された後、以下を Phase 3 で実装：

1. **Deep link 方式の紹介リンク発行**
   - 紹介者ごとに `https://t.me/<予約Bot>?start=ref_<customer_id>` を発行
   - 被紹介者がリンクから予約Botを起動した瞬間、`BookingBot.gs` の `/start` ハンドラで `ref_xxx` を解析 → REFERRALS シートに自動登録
   - 入力欄不要 → 離脱ゼロ・なりすまし不可

2. **REFERRALS シートの自動更新**
   - 既存の手動スキーマをそのまま流用
   - 予約完了時に `booking_id` 紐付け、施工完了時に `status=completed` 自動更新

3. **マイルストーン自動通知**
   - 紹介完了時に累計をカウント → 3/5/7 到達時に紹介者へ自動メッセージ
   - 1時間トリガーで未通知の達成を検出して送信

4. **管理グループへの集計レポート**
   - 月初に「先月のVIP紹介ランキング」を管理グループへ自動投稿

### 注意事項（v6 の教訓を踏まえる）

- 自動通知ロジックは `processTelegramQueue` 側に実装し、`doPost` では絶対に重い処理をしない
- マイルストーン判定の重複発火防止は `ScriptProperties` の `milestone_fired_<customer_id>_<level>` キーで管理
- VIP割引10%の適用は `BOOKINGS.payment_status` ではなく **料金計算側**で処理（status 列に値を増やさない）

## 8. オープン論点 / 今後の調整候補

- 洗車無料チケットの**有効期限**: 当面は無期限。将来チケット数が膨らんだら6ヶ月期限に
- 駐在員の**任期確認**: 7人達成時にVIP登録、口頭ヒアリングで任期把握（厳密管理は不要）
- 被紹介者の**地域制限**: プノンペン市内のみ（移動コスト的に）
- **不正防止**: 同一電話番号・同一車両ナンバーでの重複紹介は1回のみカウント
- **撤退条件**: 1ヶ月で紹介ゼロが続く紹介者には自動でリマインド送信（Phase 3）
