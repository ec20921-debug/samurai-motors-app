# SNS自動投稿 比較資料（Facebook / Instagram / TikTok）

作成日: 2026-06-21
対象: Samurai Motors の動画（`tiktok_exports/` の縦型9:16クリップ等）を SNS へ投稿する自動化の検討資料。

> ⚠️ スコープ注意: 本件は**マーケ/社内系**であり、v7（顧客対応系・3,500行目標）には**混ぜない**。
> 別スクリプト or 別サービスとして構築する（CLAUDE.md「コード肥大化防止」「顧客対応系のみ」ルール準拠）。

---

## 1. 結論サマリー

| プラットフォーム | 完全自動の公開投稿 | 補足 |
|---|---|---|
| **Facebook（ページ）** | ✅ 可能 | Graph API でリール/動画/写真投稿が公式サポート |
| **Instagram（ビジネス）** | ✅ 可能 | Content Publishing API。**動画を公開URLで置く必要あり** |
| **TikTok** | ⚠️ 当面は半自動 | Content Posting API はあるが、**アプリ審査通過まで「下書き/非公開」止まり** |
| **キャプション（投稿文）** | ✅ 可能 | クメール語＋英語＋ハッシュタグの自動生成・自動付与が可能 |

**おすすめ**: まず方式A（ノーコード）で運用を回し、効果が見えたら FB+IG だけ方式B/Cで自動化。TikTokの完全自動化（審査）は投資対効果を見てから。

---

## 2. プラットフォーム別の技術事情

### 2.1 Facebook ページ
- **API**: Meta Graph API（`/{page-id}/videos`, リールは `/{page-id}/video_reels`）。
- **必要物**: Facebookページ / Meta開発者アプリ / **ページアクセストークン**。
- **トークン運用**: 長期ユーザートークン（約60日）→ページトークンを取得。**60日ごとの更新フロー**が要る（自動更新も実装可能だが手間）。
- **GASからの実行**: `UrlFetchApp` で直接叩ける。
- 難易度: ★★☆（中）

### 2.2 Instagram（ビジネス/クリエイター・FBページ連携必須）
- **API**: Instagram Graph API の Content Publishing（①メディアコンテナ作成→②公開）。リール対応。
- **重要な制約**: 動画は**外部の公開URL**を渡す方式（IG側が取り込む）。Google Driveの共有リンクは不安定なため非推奨。
  - → 解決策: **GitHub Pages**（無料）で `tiktok_exports/*.mp4` を公開URL化すればそのまま使える。
- **レート制限**: API経由は24時間あたり概ね50投稿まで（個人運用では十分）。
- 難易度: ★★★（中〜高、URLホスティングが要る）

### 2.3 TikTok
- **API**: TikTok for Developers の Content Posting API。「Direct Post（直接公開）」と「Upload（下書き/インボックス送信）」がある。
- **最大の壁**: アプリが**TikTokの審査（App Review / Audit）**を通るまで、投稿は**自分だけ閲覧可（非公開）/下書き**に制限される。完全自動の公開投稿には審査通過が必須で、**数週間**かかることがある。
- **今すぐ可能な範囲**: APIで「下書きまで送る → スマホのTikTokアプリで1タップ公開」の**半自動**。
- 難易度: ★★★★（高、審査がボトルネック）

## 3. 3方式の比較

| 項目 | **A: ノーコード運用** | **B: ローコード自動化** | **C: フルカスタム開発** |
|---|---|---|---|
| 概要 | Meta Business Suite（FB+IG予約投稿）＋ TikTok純正スケジューラ | Make / n8n / Zapier でフォルダ監視→自動投稿 | Graph API / TikTok API を直叩きする専用スクリプト |
| FB自動投稿 | 予約投稿（手動アップ） | ✅ 自動 | ✅ 自動 |
| IG自動投稿 | 予約投稿（手動アップ） | ✅ 自動 | ✅ 自動 |
| TikTok | 純正で予約（半自動） | 下書き送信（半自動）※審査で自動も可 | 審査通過後は自動 |
| 初期準備 | アカウント連携のみ（1〜2h） | アカウント＋シナリオ構築（1〜3日） | Meta/TikTokアプリ申請＋実装（1〜2週間＋審査） |
| 月額コスト | **無料** | 無料〜約$20/月（Make/n8n/Zapierの段階課金） | ホスティング無料（GAS）。ただし開発・保守の人件費 |
| 開発工数 | なし | 小 | 大 |
| 保守 | ほぼ不要 | 低（トークン更新は半自動化） | **中〜高**（トークン更新・API仕様変更・TikTok審査維持） |
| 強み | 今週から回せる／無料／安全 | 動画を置くだけで自動投稿／費用安い | 完全自動・自由度最大（キャプション自動生成も内製） |
| 弱み | 毎回手動アップが必要 | 外部SaaS依存／TikTok公開は別途審査 | 構築・保守コスト大／トークン切れ事故のリスク |
| おすすめ度 | ◎（まず最初） | ○（FB+IG自動化の本命） | △（規模拡大後／TikTok本格運用時） |

### 補足: 各SaaSの目安（方式B）
- **Make.com**: 無料枠 約1,000オペレーション/月、有料 約$9〜/月。FB+IG対応、TikTokはBusiness連携で下書き中心。
- **n8n（セルフホスト）**: ソフト自体は無料（要サーバー）。自由度高め。
- **Zapier**: 約$20〜30/月。とっつきやすい。
- **Metricool / Buffer / Publer**: FB+IG+TikTok予約に対応する投稿管理SaaS（月数$〜）。「ほぼノーコードで3媒体まとめて予約」したいなら有力。

## 4. 推奨ロードマップ（段階導入）

1. **今週（方式A）**: Meta Business Suite で FB+IG を予約投稿、TikTokは純正スケジューラ。キャプションは本資料の自動生成テンプレを使用。→ まず投稿を習慣化し、反応データを集める。
2. **2〜4週目（方式B）**: 反応が良ければ Make/Metricool 等で **FB+IG を完全自動化**（GitHub Pagesの動画URLをトリガー）。TikTokは下書き送信の半自動を継続。
3. **本格化フェーズ（方式C/審査）**: TikTokの投稿量が増え、完全自動の価値が出てきたら TikTok for Developers の審査に着手。FB+IGも内製スクリプト化を検討。

## 6. キャプション自動生成の方針（クメール語＋英語＋ハッシュタグ）

- 1動画につき **クメール語 → 英語 → ハッシュタグ** の順で1本のキャプションを生成。
- **言語ルール準拠**: 集客対象はカンボジア人顧客＝クメール語メイン、英語併記（CLAUDE.md 言語表）。
- ハッシュタグは「ブランド固定タグ＋地域タグ（プノンペン/カンボジア）＋サービスタグ」を組み合わせ。
- 文面テンプレと10本分のサンプルは別ファイル **`sns_captions_km_en.md`** に用意。
- 自動化時は「動画テーマ → キャプション」を対応表から差し込むだけ（方式B/Cでテンプレ流し込み）。

## 7. リスク・注意点

- **トークン切れ事故（FB/IG）**: 60日更新を忘れると投稿停止。→ 更新リマインド or 自動更新を必ず設計。
- **TikTok審査**: 審査落ち/遅延がありうる。完全自動は「できたらラッキー」程度に見積もり、当面は半自動前提。
- **著作権（音源）**: 今回のBGMは自前合成で権利クリア。TikTok内トレンド音源を使いたい場合は**アプリ内で差し替え**が必要（API投稿だと使えない）→ 媒体ごとに音の戦略を分けるのも手。
- **公開アカウントへの投稿**: 自動化は「誤投稿」が一気に拡散するリスクがある。**初期は必ず下書き/予約でレビューを挟む**運用を推奨。
