## 1. 経緯

2026-05-18、Ron-kun から「お客さんとのやり取りで電話番号が分からないと困る」との指摘あり。当初はシステム改修（Telegram `request_contact` 機能の実装 等）を検討し、調査・設計を進めた。

しかし同日中に Ron-kun と詳細を OJT した結果、**システム改修不要** との判断に到達。本書は調査内容・判断・教訓を記録するもの。

---

## 2. 調査結果（実装判断のための事実確認）

| 項目 | 状態 | 場所 |
|---|---|---|
| CUSTOMERS シート「電話番号」列 | ✅ 定義済み（5列目） | `v7/Setup.gs:28` |
| 新規登録時の値 | ❌ 空文字を書き込み | `v7/Router.gs:240`, `v7/ForumTopicManager.gs:79` |
| Telegram `request_contact` 実装 | ❌ 未使用 | コード内に該当処理なし |
| booking.html の入力フォーム | ❌ 電話フィールドなし | `booking.html:1520-1528` |
| **顧客個別チャット機能** | ✅ **既に動作中** | `v7/ForumTopicManager.gs` 経由のフォーラムトピック |

→ **スキーマと個別チャット機能はすでに揃っている**。足りないのは「使い方の浸透」だった。

---

## 3. 真の原因 — 機能ギャップではなく**操作習熟ギャップ**

Ron-kun は **そもそも顧客一人ひとりに個別メッセージを送る方法を知らなかった** ことが判明（同日 OJT で説明）。

| 観察 | 詳細 |
|---|---|
| 当初の認識 | 「顧客にメッセージを打てない」 → システム的制約と思っていた |
| 実態 | フォーラムトピック内で個別チャットは完全に可能 |
| 原因 | Telegram のフォーラムトピック UI 操作が直感的でない + 説明機会不足 |
| 対処 | 2026-05-18、現地で OJT 実施 |

---

## 4. 採用方針

| 項目 | 方針 |
|---|---|
| システム改修 | **なし**（現行アーキテクチャ維持） |
| 電話番号取得 | **必要時にロン君が個別チャットで聞く**（クメール語ボイス可、テキスト可） |
| 記録先 | CUSTOMERS シートの既存「電話番号」列に手動入力 |
| バックフィル | 不要（個別対応の自然な蓄積に任せる） |

---

## 5. この件から得た教訓 — 機能不足の前に「使えてるか」を疑う

| 教訓 | 今後への示唆 |
|---|---|
| **症状 ≠ 原因** | 「困った」報告は機能不足とは限らない。まず「機能の有無」と「使い方の浸透」を分離して確認 |
| **OJT 機会の不足** | 鈴木が現地に行かないと Ron-kun の理解度が見えない。**非同期チュートリアル整備の検討余地** |
| **マニュアルの実効性検証** | [`manual_staff_km.md`](manual_staff_km.md) が現場で使われているか、有効な記載か再点検すべき |
| **早合点による開発負債リスク** | 本件で実装に踏み切っていれば、不要な分岐とメンテコストが永続化していた |
