## 0. 仕組みの全体像（1分で理解）

- **ボットは増やさない**。既存の予約Bot 1本を全店で共用し、店ごとの区別は
  ディープリンク `t.me/<予約Bot>?start=shop_<shop_id>` で行う → **トークン新規発行ゼロが標準**
- 店舗の実体は既存の **店マスター**（v7 Database・shop_id体系）
- 店⇄グループの紐付けは v7 Database の **「Bot連携」シート**（自動作成）
- 精算集計は既存の **コミッション台帳**（勤務用GSS）から shop_id 別に自動集計

### 💰 精算ルール（2026-08-09 Daisuke 決定）
1. お客様は **店に全額支払い**（受付の信頼できる人がお金を扱うのがカンボジアの自然な形）
2. 店は **30%を自分の取り分**としてその場で確保
3. 当社の**70%は施工完了時にその場回収**（現金 or ABA）。出張施工でスタッフが現場にいるので売掛を残さない
4. 回収したら **コミッション台帳の支払ステータスを「支払済み」に更新**（集金者=「店」の行）
5. 未回収分は月次レポートに「⏳ Not yet settled」として双方に表示 → 督促の代わり

## 2. 日常運用（日本側は原則ノータッチ）

- 現地がフォーム入力 → 自動で shop_id・QR・ワンタイムコードが管理グループに届く
- 現地がグループ作成→Bot招待→`/register <コード>` → 完了通知が届く
- 毎月1日: 店別レポートが各店グループ＋管理グループに自動送信
- **日本側がやること**: 月次サマリーで未回収の多い店がないか眺めるだけ
- **グループへの通知の言語（2026-10-26〜）**: v7 Database「店マスター」の「グループへの通知の言語」列（プルダウン）で店ごとに変えられる。並べた順に出す。**空欄＝クメール語＋英語＋日本語**（Daisuke「車屋とかの提携店は、クメール語と英語と日本語に」「ケースバイケース」）。対象 = 連携完了の返事・QRからの来店の知らせ・あいさつ文・作業の開始/完了と写真・請求・月次レポート（**請求だけは日本語を出さない**＝クメール語＋英語・2026-10-31 Daisuke「長くて見にくい」）。変えてから最大5分で反映（あいさつ文は連携した時の1回だけなので、連携の前に決める）。営業ボード「🔗 提携店QR・グループ連携」タブの「グループへの通知の言語」列で、今どうなっているか分かる。レジデンス等（英語）のグループは固定でこの列を使わない。個人提携は空欄＝英語＋クメール語で、この列の日本語・英語・クメール語を使う（2026-10-28〜。それまでは空欄＝日本語）
- 新しいクメール語の文は Panha を通す（v7/PartnerLang.gs・v7-operations/PartnerLangOps.gs。文言は両方にあるものがあるので、直すときは両方）

## 2.5 すでに専用QRを配った店をグループ連携する（2026-10-20 追加）

営業で先に専用QR（`start=shop_<店マスターの既存shop_id>`）を配った店は、**フォームを使わない**（フォームは新しい shop_id を採番するので、配った QR と食い違う）。

1. 店マスターの「QRリンク(BookingBot)」に、その店の予約Botリンク（`https://t.me/SAMURAI_MOTORS_BOOKING_BOT?start=shop_<shop_id>`）が入っていることを確認する
2. v7-operations の GAS エディタで `issueShopLinkCodesForQrShops()` を実行
   → Bot連携シートに「待機中」の行（既存の shop_id のまま・6桁コード）ができ、管理グループのパートナートピックに **店名とコードの一覧** が届く。何度実行しても二重には作らない（発行済みの店は同じコードを再掲、連携済みの店は ✅ 表示）。【サンプル】行は対象外
   - 店を指定して出すときは `issueShopLinkCodes(['SHOP-…', 'SHOP-…'])`
3. 店ごとに、お店の人と Telegram グループを作り予約Botを招待 → `/register <コード>` を送る → ✅ で完了
   - **あいさつ文は Bot が自動で送る（2026-10-24〜）**: 「✅ Connected!」の直後に、営業ボードと同じあいさつ文（店マスター「グループへの通知の言語」の順。空欄＝クメール語＋英語＋日本語）を予約Botが1回だけ送る。手で貼らない（二重になる）。送れなかった時は毎時の安全網が、連携から7日以内の店に限って送り直す（v7/ShopGroupGreeting.gs・送信済みの印は Script Properties `shop_greeting_sent_<shop_id>`）。文言を直すときは v7/ShopGroupGreeting.gs と v7-operations/ScoutBoardShopLinks.gs の両方を直す

**一覧はここ（2026-10-22〜）**: 営業ボード「SAMURAI SCOUT 営業ボード」の **「🔗 提携店QR・グループ連携」タブ**（1時間ごとに自動更新・見るだけ）。店ごとに 連携の状態・作るグループ名・グループで送る文（/register）・あいさつ文（クメール語＋英語・Panha 校閲 provisional）・予約QRのURL・流入（QRを読んだ人→予約画面→予約→施工→売上・取り分）・実際のグループ名。作り方の手順もタブの上にある（v7-operations/ScoutBoardShopLinks.gs）

**現場でQRシールを作る流れ（2026-10-22〜・正本）**: Daisuke「営業ボードから顧客のQR URLをスマホでコピーして、アプリにコピペで現場ではQRシールを印刷する。流れと記録の最適化を」
1. お店がOK → 営業アプリ（SAMURAI SCOUT）のお店の画面「🔗 QRシール・お店のグループ」→「このお店のQRを出す」。店マスター「QRリンク(BookingBot)」に書かれ、Bot連携に6桁コードが出る（管理グループのパートナートピックに通知）。その場で使える（ボードの1時間更新を待たない）
2. 「📋 URLをコピー」→ ラベル印刷アプリに貼り付けてシールを印刷 → 自分のスマホで1回読んで確認（カードの「QRを読んだ人」が増える）
3. 「🏷 QRシールを渡した」で枚数を記録 → v7 Database「QRシール記録」タブに1行（記録者・日時）、店マスター「QRシール枚数／QRシール最終日／QRシール記録者」に累計（v7-operations/ShopQrSticker.gs）
4. 「📋 グループ名をコピー」「📋 送る文をコピー」でグループを作り /register → ✅
- 記録の大元は v7 Database（店マスター・Bot連携・QRシール記録）。営業ボードは見るだけ（列順は 店名 → QRのURL → 連携 → 送る文 → シール枚数）
- 旧ファイル「SamuraiMotors_提携店専用QR_URL一覧_2026-10-20」（Drive）は使わない（中身は営業ボードと同じ・流入分析タブは未接続のまま）
- QRリンク欄に別の店のリンクが入っている店は、アプリで発行できない（「別のお店のもの」と出る）→ 店マスターを手で確認する

**決済QRについて（2026-10-20 修正）**: 店QR経由のお客様には、**店舗グループが未連携でも** 当社の決済QR・支払いのご案内を送らない（お客様は店に定価を払うため）。管理グループの作業終了通知に「🏪 提携店経由」と出る。
- 店扱いになる条件: 店QRのリンクの shop_id が **店マスターにあり**、Bot連携で **停止になっていない** こと。店マスターに無い・停止中の店のリンクから来た人は通常のお客様として案内し、管理グループに「⚠️ 店として扱わなかった」と出る
- **最後に読んだQRが優先**: 店QRを読むとレジデンス等の流入元（src_ref）は外れ、有効な流入元QR（Picasso 等）を読むと店の紐付け（shop_ref）は外れる
- 予約なしの手動ジョブの「支払いのご案内」: 現場アプリの支払区分が 現金・ABA なら送る（現場の明示が優先）／提携店払い・無料なら送らない／未選択・後払いなら店QR経由のお客様には送らない
- 店マスターが一時的に読めない時は店扱い（当社QRを送らない側）に倒す
- **写真共有の告知（2026-10-21 Daisuke 決定）**: 店QRから来たお客様への歓迎メッセージで「作業前後の写真はこのお店にも共有されます」とクメール語＋英語で一言伝える（BookingBot.gs sendWelcomeMessage の referralLine）。現場が口頭で伝える必要はない
- 店を通さず当社で集金する例外だけ `retryPaymentQR("<予約ID>", true)` で送れる（第2引数なしだと何も変えずに止まる）
- 関連ファイル: v7/ShopRouting.gs（getValidShopRef_ / lookupShopMaster_）・v7/PaymentManager.gs・v7/ManualCustomerLink.gs・v7-operations/ShopLinkCodes.gs

## 2.6 レジデンス等（流入元）の提携先グループに通知する（2026-10-26 追加・第1号 = Picasso City Garden）

Daisuke「ピカソがつくってくれたTelegramグループに通知が各種されるようにしたい」。車屋の店舗グループと同じ Bot連携・/register を使うが、**流すものと集金の扱いが違う**。

- **流すもの（英語）**: ①予約が入った（日時・部屋番号・車種・サービス）②作業開始（Before 写真）③作業完了（After 写真・所要時間）。**名前とナンバーは載せない**。**月次レポート（金額・紹介料）は送らない**（v7-operations sendShopMonthlyReports が流入元タブの shop_id の店を除外）
- **対象の予約**: 流入元の専用QR（Picasso なら picasso_tg / picasso_signage / picasso_poster / picasso_flyer）から入った予約のうち、**予約確定の時点でグループが連携済み**で、確定文に「管理側にも共有されます」を出したものだけ（Script Properties `srcgrp_<予約ID>` が印）。**連携より前の予約・予約なしの手動ジョブは流さない**
- **集金には一切関係しない**: お客様は従来どおり当社に ABA で払う（店 QR の shop_ref とは別物）。流入元の提携先は **現場アプリの「どの提携店？」に出ない・店グループへの請求を送らない・その shop_id の店QRは店扱いしない**
- **つなぎ方**: 流入元タブの `shop_id` 列（Picasso = 店マスターの Picasso の行）→ Bot連携の同じ shop_id の行（状態=連携済・グループchat_id）
- **住民への一言**: グループが連携済みのときだけ、歓迎文と予約確定文に「予約の内容と写真は管理側にも共有されます」（英語＋日本語）が出る
- 連携の手順: ① **先に流入元タブの `shop_id` を入れておく**（順番が逆だと車屋用のあいさつ文＝月次の金額に触れる文が出て、取り消せない）② Bot連携に、その shop_id の「待機中」行（6桁コード）を作る（v7-operations `issueShopLinkCodes(['<shop_id>'])`）③ 先方のグループに予約Bot（@SAMURAI_MOTORS_BOOKING_BOT）を招待 ④ グループで `/register <コード>` → ✅。連携完了の文とあいさつ文は流入元用（英語・住民のご予約が届く旨）が自動で出る
- **流入元タブが読めない時**: 請求・あいさつ文は送らない側に倒す（あいさつ文は毎時の安全網が再試行）。月次レポートは全店の送信を止めて管理グループへ知らせる → タブを直してから `sendShopMonthlyReports()` を手で実行
- **届かなかった時**: 管理グループに「⚠️ 提携先グループへの通知が届きませんでした」が出る（自動では送り直さない）。「グループの ID が変わっています」と出たら、Bot連携の「グループchat_id」を新しい ID に直す
- **先方がグループを作り直した時**: 旧グループの Bot連携の行を「停止」にしてから、新しいコードで /register（連携済みが2行あると先の行に送り続ける）
- **流さないもの（今は）**: 予約のキャンセル・日時の変更、月次のまとめ。写真は無加工なので **ナンバーが写ることがある**（本文には載せない）
- 営業ボード「🔗 提携店QR・グループ連携」タブの「あいさつ文」列と、連携コードの管理通知の「月次レポートが届く」は車屋向けの文。流入元の提携先には貼らない（あいさつ文は Bot が流入元用を自動で送る）
- 関連ファイル: v7/SourceGroupNotify.gs（本体）・v7/BookingLogic.gs（予約確定の直後）・v7/JobManager.gs（開始・完了）・v7/ShopGroupGreeting.gs・v7/ShopRouting.gs・v7/SourceCampaign.gs・v7-operations/ShopProvisioningManager.gs

## 2.7 新しい QR を出したら「開通テスト」（2026-10-26 追加・車屋も流入元も共通）

Picasso で「QR から入ったのに一般向けの画面になる」が起きた教訓（OPS_LESSONS #11）。QR を配る前に、**その QR を初めて使う Telegram アカウント**（家族・スタッフの予備など。Daisuke の普段のアカウントは紐付けが変わるので使わない）で次の2通りを試す。

| # | 操作 | 期待する結果（流入元＝Picasso 等） | 期待する結果（車屋の店QR） |
|---|---|---|---|
| 1 | QR → START → **Bot の返事を待ってから** 左下の Booking | 英語＋日本語・割引価格・部屋番号の欄（場所が決まっている流入元） | 定価・クメール語＋英語（一般と同じ）。歓迎文に店名と「写真は店にも共有」 |
| 2 | 別の新しいアカウントで QR → START → **返事を待たずにすぐ** Booking | はじめは一般向けでも、**2分以内に自動で住民向けに切り替わる**（「住民向けの料金に切り替えました」が出てメニューに戻る） | 1 と同じ（店QRは画面が変わらないので影響なし） |
| 3 | 管理グループ | 「🏢 …の専用QRから流入」（無効の行なら「流入元タブで無効のため通常の歓迎」）／新規顧客 | 「🏪 提携店QR経由の新規流入」・店グループが連携済みなら店に来店通知 |

- 2 で切り替わらない → 流入元タブのその行（有効・言語・場所名・割引）が他のチャネルの行と同じか見る。それでも直らなければ開発側へ
- 料金の決まり（2026-10-26 Daisuke 確認）: **車屋の店QRのお客様は定価**（店が受け取り、店の取り分＝紹介料率・空欄は30%、当社は残り70%を店から ABA QR で受け取る）。**車屋自身の在庫車は30%オフ**（当社は定価の70%。現場アプリは店ごとの紹介料率で計算するので、率を変えた店はその率のオフ）。**流入元（レジデンス等）は流入元タブの割引**（Picasso 住民は20%オフ・出張料なし・当社集金）
- **全体キャンペーン（設定タブの割引）は店QRのお客様には付かない**（2026-08-10 裁可⑩）。2026-10-26 までは歓迎文のバナーを隠すだけで、予約画面と予約の金額には効いていた → 予約画面（`booking_init` が campaign を返さない）と予約作成（`createBooking`）の両方で外すように修正。画面でキャンペーン価格を見せたのにサーバーで外れる時（QR 直後に開いた等）は、予約を作らず画面がメニューに戻る（`PRICE_CHANGED`）
- **一斉配信（キャンペーン配信・予約配信）も店QRのお客様には送らない**（2026-10-26 Daisuke「外して」。割引の無いお知らせも含む）。判定は決済QRと同じ（店マスターに無い・停止中の店のリンクから来た人は通常のお客様として届く）。プレビューと最終確認に「提携店QR経由の ◯名は除く」と出る（v7/CampaignShopFilter.gs）。判定できない時は送信を止める

## 2.6 個人提携（個人の紹介者・2026-10-26 追加・第1号 Hiro Sato さん）

Daisuke「お店、車屋提携、個人提携みたいな感じがこれからも増えていく」。決定ログ: Vault/01_Personal/Decisions/2026-10-26-motors-individual-partner-type.md

| | 車屋・お店（従来） | 個人提携 |

| 紹介料 | 現場アプリ・営業アプリで台帳に記帳 | 毎月1日に**自動で台帳に記帳**（作業完了・清算済みの予約から） → 月報 → **10日までに ABA で支払い** |
| 本人の利用 | — | **予約の時に30%引き・紹介料なし**（2026-10-27。店マスター「本人chat_id」に本人の Telegram chat_id を登録した時。未登録の間は、本人が紹介QRを読めば従来どおり定価＋紹介料30%） |

### 最初の紹介者で固定（2026-10-27 追加）

- **紹介元は最初の紹介者のまま**: 有効な紹介元があるお客様が別の提携先・紹介者のQRを読んでも変えない（以前は「最後に読んだQRが優先」）。歓迎文は最初の紹介者のお客様としての文、管理グループに「🔁 …最初の紹介元のまま」
- **既存客は対象外**: 紹介なしの予約（キャンセル以外。作業前の予約確定も含む）があるお客様は、紹介QRを読んでも紹介元を付けない（通常のお客様として案内・管理グループに「ℹ️ …既存客は対象外」）。予約タブを読めない時は付ける側に倒し、管理グループに知らせる
  - 紹介者ご本人は、既存客でも「本人chat_id」を登録すれば本人割引（予約の時に30%引き・紹介料なし）になる。登録済みの本人がどの紹介QRを読んでも、紹介元は付けない
- 紹介元が停止中・店マスターから消えた時は、無いのと同じ（次に読んだQRが付く）
- 個人提携は当社集金なので、レジデンス等の流入元と両立する（どちらのQRを読んでも、もう一方を外さない）。**車屋は従来どおり**、流入元QRを読むと店の紐付けを外す／店QRを読むと流入元を外す
- 店QRを読んだ記録（ファネルログ `shop:<id>`）は、紹介元を付けない時も残る（シールの動作確認用）
- 手で直す時: Script Properties `shop_ref_<chat_id>`（紹介元。直すと付いた日は自動で今日から）と、予約タブ「紹介元shop_id」（その予約の紹介元）
- **紹介の期限 = 付いた日から12か月**（8/9 決め事④・2026-10-27 Daisuke「12ヶ月で良い」。車屋も個人提携も同じ）
  - 期限が過ぎたら紹介元は無いのと同じ（紹介料・紹介割引なし／全体キャンペーン・一斉配信は通常どおり／決済は当社）。期限の内側に作った予約は、作業が期限の後でも予約の「紹介元shop_id」で紹介料が付く
  - 付いた日のちょうど12か月後の日に切れる（2026-10-28 に付いたら 2027-10-27 まで有効）
  - 同じQRを読み直しても期限は延びない。期限後に付け直せるのは、キャンセル以外の予約が無い人だけ（予約がある人は既存客）
  - 付いた日 = Script Properties `shopref_at_<chat_id>`（"<shop_id>|<yyyy-MM-dd>"。紹介元と店が一致しない日付は無いのと同じ＝今日から数える）。この版より前の紐付けは、本番に出したあと最初の毎時処理（または最初の読み取り）で一括して、その日が付いた日になる（印 = `shopref_dates_migrated_v1`）
- **紹介者ご本人の予約**（2026-10-27 Daisuke）: 店マスター「本人chat_id」に登録した本人の予約は、予約の時に（紹介料率＋紹介割引）% 引き（標準30%・上限30%）で、紹介料は付けない（予約の「紹介元shop_id」は空・月報にも入らない）。紹介した友達の予約は今までどおり、定価であとでまとめて紹介者に30%バック。流入元の特典（Picasso 等）が効く予約では本人割引を使わない。手動ジョブ（現場アプリ）の本人の仕事は紹介料なし・割引はスタッフが金額で入れる
  - 本人の予約が入ると、本人のグループにも知らせる（2026-10-28 Daisuke・v7/IndividualPartnerNotice.gs）: 予約番号・日時・車種・メニュー・金額（割引前 → 割引後・本人割引の率）・地図、出張作業ならコンドミニアム等に停める時のお願い（駐車場所が決まったらナンバーと停めた階をこのグループへ）。出張料がある時だけ出張料と合計の行（「出張料なし」とは書かない）。店舗作業は地図と駐車のお願いを出さない。紹介料・月報には入れない（「紹介元shop_id」は空のまま）
- **紹介されたお客様が紹介者になった時**: 本人の利用は最初の紹介者のまま（2026-10-27 Daisuke）＝ほかの人の紹介で来ていた人は「本人chat_id」を登録しても本人割引にならない。最初の紹介者が「本人で良い」と言った時だけ、Script Properties の `shop_ref_<chat_id>` を消して「本人chat_id」を登録する（以後その人の予約は本人割引）
- **高額メニューも同じ率**。メニューは組み合わせて予約でき（例: 無水洗車＋窓撥水＋ヘッドライト）、紹介割引・紹介料は組み合わせた合計に効く。高額メニューを予約で受けるかは別途検討
- **標準の配分 = 紹介料30%**（紹介割引率は空欄=0）。紹介者が希望した時だけ、紹介料の一部を紹介されたお客様の割引に回す（紹介者ごとの設定）。知り合い1人だけに還元したい時は、紹介者が自分の紹介料から送ればよい（2026-10-27 Daisuke）

## 2.8 提携の管理 — 書くのは店マスター、見るのは営業ボード（2026-10-27 追加）

Daisuke「提携という軸で1つで管理できたら」「タブで個人提携、車屋提携、商業施設提携みたいに分ける」「V7 の方にないとまずいものは V7 にも必要」

- **入力は v7 Database「店マスター」だけ**（予約Bot・月報・現場アプリが直接読む大元）。提携種別・紹介料率・紹介割引率・グループへの通知の言語・本人chat_id・紹介チラシURL など、Bot が使うものはすべてここ。グループのつながりは「Bot連携」、本人登録の名前・日時・リンクは予約Botが店マスターに書く
- **見るのは営業ボード「SAMURAI SCOUT 営業ボード」**（v7-operations が1時間ごとに店マスター・Bot連携・予約・売上から作り直す。手で書いても次の更新で消える）
  - 「🙋 個人提携」: 番号・本人登録（✅ 名前・日時／⏳ リンク送付済み／— 未登録）・本人登録リンクの送付（リンク本体は出さない）・チラシの版と枚数・最後に送った日と版・紹介料%・紹介割引%・本人の割引%・グループの言語・流入（QRを読んだ人→予約画面→予約→施工→売上）・紹介料
  - チラシの履歴は v7 Database「紹介チラシ送付履歴」（どの版をいつ誰に送ったか・予約Botが書く／手で送った分は Claude）と「紹介チラシの版」（版ごとの変わったところ・Claude が書く）。2026-10-27 Daisuke「どのバージョンを送ったのか履歴もしっかり GSS で管理」
  - 「🚗 車屋提携」「🍽 飲食店提携」「🏠 レジデンス提携」「🏢 商業施設提携」: 同じ流入の数字と連携の状態＋店名の右に「お金の流れ」（店集金／当社集金）
  - **タブは相手の種類で分ける（2026-10-29〜）**。Daisuke「車屋提携のタブの中にシティゴルフが入ってるけど、これは商業施設提携の方に」「ピカソはレジデンスだけど、商業施設ではないよね？」。それまでは「お金の流れ」で分けていた
  - 分類 = 店マスター「営業ボードの分類」（プルダウン: 車屋・飲食店・レジデンス・商業施設）。空欄は自動: 飲食店の型 → 飲食店／業種にゴルフ・ホテル・モール・商業・オフィス → 商業施設、コンド・レジデンス・マンション → レジデンス、飲食・レストラン・カフェ・パブ・バー → 飲食店／流入元の提携先 → レジデンス／ほか → 車屋。個人提携はいつも「🙋 個人提携」

  - 分類は**見せ方だけ**。お金の流れ（店集金か当社集金か）は「提携種別」と流入元タブで決まり、分類を変えても変わらない（v7-operations/ScoutBoardShopLinks.gs scoutLinksCategory_）

  - 「📘 提携の型」: 型の選び方・4つの型の違い・共通のきまり（店のデータは出さない決まった文。🔗 タブのすぐ右に自動で作る・v7-operations/ScoutBoardPartnerTypes.gs。中身の正本は suzuki-empire-day1 docs/MOTORS_PARTNER_TYPES.md。文を変えたら SCOUT_TYPES_VERSION を上げる＝その時だけ書き直す）。2026-10-29 Daisuke「この GSS に入れてほしい」

## 3. ブランドBot希望の店が出たら（+10分）

フォームの「ブランドBot希望=はい」通知が来た場合のみ:

1. BotFather で新Bot作成（命名例: `<shop>_samurai_bot`）
2. トークンを **v7 の Script Properties** に `BOT_TOKEN_SHOP_<shop_id>` で登録
   - ⚠️ **絶対にコード・リポジトリ・GSS・チャットに貼らない**（2026-07-03 トークン露出インシデントの教訓）
3. マルチテナントのポーリング組み込みは未実装（需要が出た時点で BotPoller 拡張を実装）。
   それまでは標準方式（共用Bot＋専用グループ）で提供し、Bot名義だけ待ってもらう
4. 露出事故時: BotFather で即 revoke → 新トークンを再登録

## 4. トラブルシューティング

| 症状 | 対処 |
|---|---|
| /register にBotが無反応 | Botがグループに入っているか確認。ポーリングは1分間隔なので少し待つ |
| 「Code not found」 | コード転記ミス or 既に使用済み。フォーム再送信で新しい行とコードを発行 |
| QRリンクが開けない | Driveの共有設定（リンクを知っている全員）を確認 |
| QR から来たのに予約画面が一般向け（割引なし・クメール語・地図） | START の直後（最大1分）に Booking を押すと起きる。初めてのお客様は2分以内に自動で切り替わる。登録済みのお客様は予約の確定時に切り替わる。すぐ直したい時はアプリを閉じて開き直す（OPS_LESSONS #11） |
| 月次レポートが店に届かない | v7-operations の Script Properties `BOT_TOKEN_BOOKING` 未登録が典型。手順1-2を実施 |
| フォーム項目を変更したい | `SHOP_PROV_FIELDS` のラベルとフォームのタイトルは**1文字も違わず一致**が必須。両方直す |
